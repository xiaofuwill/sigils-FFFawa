## 二、不可破坏的约束（贯穿全部改动）

1. CC 游戏端是 Factory 数据与持久化的唯一权威；relay 只转发。
2. 不修改 WebSocket 协议、`factory.json` 结构、过滤器语法与 Create 运输行为。
3. 不做乐观写入：所有修改等 CC 的 `ConfirmationResponse.diff` 或 `CcUpdatedFactory`。
4. 所有 mutation 经过 M5.5.1 写入门禁：同一时刻最多一个 mutation；stale 时全部冻结。
5. 不实现没有原子事务保证的跨机器槽位迁移；不伪造合并成功。
6. 模拟器测试不得描述成真实游戏测试。

## 三、M6：交互语义恢复

### 3.1 先调查旧版，再写代码

调查对象：`SIGILS-upstream-master/SIGILS-master` 的 `client/src` 与 `computercraft/sigils`。

关键事实（详见 `docs/M6-旧版交互对照.md`）：

- 画布上的“容器大框”就是 `slot-group` 节点（Group），v4.3 没有独立 Container 实体。
- 容器合并 = `combineGroups`：同一机器、同 fluid 类型，`GroupEdit`（目标槽位合并排序）+ `GroupDel`（源），装在一个 `BatchRequest`；CC 对整批只 `saveFactory` 一次。
- 槽位拖动 = 同一机器内把单个槽位拆成新容器；源容器只剩 1 个槽位时不动。
- 机器框合并、外设徽章拆分在旧版存在，但不在 M6 任务书范围，决定不实现。
- Machine 没有外设 ID 字段；`Machine.id` 就是外设 ID，分组 ID、槽位 `periphId`、管道端点都由它派生。

### 3.2 实现与决策

| 能力 | 实现 | 决策理由 |
|---|---|---|
| 槽位拖动 | `buildGroupSplit` + `GroupAdd`/`GroupEdit` 单批提交；落点写入新容器 `x/y` | 与旧版一致；源容器不可变空，避免空容器 |
| 容器合并 | `canMergeGroups` 预校验 + `buildGroupMerge`；UI 拖动整张容器卡片，绿色高亮 + 确认框 | 避免把“合并”做成菜单按钮或单纯槽位移动；破坏性操作需确认 |
| 合并排序 | `slot` 升序 → `periphId` 字典序 | 对齐上游 `combineGroups` |
| 外设 ID | 只读展示 + `MachineReassignPeriph` 协议提案 | 现有 `MachineEdit` 只写对象字段，无法重命名 map key/分组 ID/槽位引用/管道端点，强写会产生损坏状态 |

### 3.3 验证

- 新增 `tests/container-merge.test.ts`；`protocol-sim.test.ts` 增加合并用例：目标槽位、源删除、机器 `groups` 更新、关联管道级联删除、客户端 diff 与服务端一致。
- 浏览器实测：拖动 Overflow 到 Main，高亮与确认正常，合并后 Main 为槽位 1–6；重连后重新 `FactoryGet` 结果一致。

## 四、M6.1：第一轮实测反馈

### 4.1 问题一：容器末尾槽位被遮挡

**第一次判断（错误）：** 以为只是槽位 `box-sizing` 问题，给 `.group-slot` 加了 `border-box`，并改成 9 列。

**复测仍失败：** 27 槽容器第 9 列仍被裁。用浏览器读取 DOM 尺寸后定位真因：

- React Flow 默认 `.react-flow__node` 自带 `padding: 10px` 与边框；
- 节点 `style.width = 266px` 是 border-box，内容区只剩 `244.4px`；
- 容器内部可用宽度 `228.8px`，而 9×26 + 8×2 = `250px`，必然溢出，被 `overflow: hidden` 裁掉。

**最终修复：**

1. 节点 wrapper 显式 `padding: 0 / border: none / background: transparent`，让布局宽度等于计算宽度；
2. `.group-node`、`.machine-node` 使用 `border-box`；
3. 槽位容器改为固定列数 CSS Grid（`repeat(columns, 26px)`），不再依赖 flex 换行。

**验证：** 27 槽位实测 3 行 × 9 列，`.group-slots` `clientWidth = scrollWidth = 250`，无裁切。

### 4.2 问题二：移除「分组槽位」面板

用户明确槽位不需要面板式编辑，槽位操作只服务于容器合并。处理：

- 删除右侧「分组槽位」卡片（勾选、保存槽位、移动槽位）；
- 删除相关状态、处理函数和「可恢复槽位」卡片；
- 槽位只保留拖动：拖单个槽位拆新容器，拖整个容器合并。

**取舍：** 删除「可恢复槽位」后，同一外设仍被其他容器使用时，被删容器的槽位无法恢复；已在验收记录中标注限制。

### 4.3 问题三：删除容器后可找回

**用户预期：** 删除容器后，容器回到「可用外设」区，可重新拿取。

**分析：** 现有协议没有“把外设放回 available”的消息；CC 只在启动/外设插拔时重算 `available`。因此不能直接改 `available`。

**方案：** 客户端维护会话级“已释放外设”：

- 每次收到权威 Factory 更新后，对比上一帧与当前帧：
  - 上一帧存在、当前不再被任何容器引用、且不在 `missing`/`available` → 判定为已释放；
- 在「可用外设」中展示并标记「已释放」，点击「添加为机器」发送 `PeriphAdd`；
- 删除失败时 Factory 不变，因此不会误释放；重连/离线时清空释放列表。

**为什么不乐观加进 available：** 违反“CC 权威、无乐观写入”；若删除失败会出现幽灵条目。

**验证：** 删除 27 槽容器 → 可用外设出现 `minecraft:barrel_0`（已释放）→ `PeriphAdd ok=true` → 机器/容器重建。

**已知限制：** mock CC 未登记 barrel 容量，重建实测为 1 槽；真实 CC 按外设实际槽位数创建。

### 4.4 名称与槽位显示

- `Inventory` → 物品槽、`Fluid tank` → 液体槽：仅显示映射，不改写游戏端昵称（避免为了 UI 文案污染 Factory 数据）。
- 液体槽位改为编号显示（1、2、3…），不再显示「液」。
- 术语统一为「容器」。

## 五、M6.2：第二轮实测反馈

### 5.1 管道无法删除（根因有两层）

1. **命中被遮挡**：机器框节点覆盖了整个机器区域，而 React Flow 的节点层在边层之上，机器内部的管道无法被点选。
2. **没有删除入口**：只有键盘 Delete，且用户常用 Backspace。

**修复：**

- 机器节点 wrapper `pointer-events: none`，仅标题/别名/计数恢复 `auto`，机器框空白区域让位给管道；机器底色改半透明，管道可见；
- 检视面板新增「删除管道」按钮（`PipeDel`）；
- `deleteKeyCode` 同时支持 Delete / Backspace；
- 机器/容器节点 `deletable: false`，防止键盘删除只删本地节点而不发送 CC 级联删除。

**权衡：** 机器只能从标题区域选中/拖动，换取框内管道可点击；这是有意的交互取舍。

### 5.2 管道无法命名

- 检视面板新增「管道名称」，与过滤表达式一起通过 `PipeEdit { nickname, filter }` 提交；
- 边标签显示「名称 (过滤表达式)」，无名称时回退到过滤表达式或 mode。

### 5.3 机器显示外设原始 ID

- 机器节点标题固定 `machine.id`（即外设原始 ID），昵称作为「别名 · …」单独展示；
- 检视面板、删除确认、统计术语统一；
- 改名只改 nickname，不改变任何引用。

### 5.4 验证

浏览器实测：机器内 `#warehouse` 管道可点选 → 改名后标签「主输入 (#warehouse)」→ 删除后边消失；点击机器标题显示 `minecraft:chest_0`；无 console 错误。mock 日志记录 `PipeEdit ok=true`、`PipeDel ok=true`。

## 六、过程中的问题与反思

| 现象 | 原因 | 处理与教训 |
|---|---|---|
| 第一版裁切修复无效 | 只改了槽位自身 `box-sizing`，没检查 React Flow 节点 wrapper 的默认 padding | 布局问题必须量 DOM，不靠猜；框架默认样式要显式覆盖 |
| 删除容器“消失” | GroupDel 后外设仍连接但不在任何 Group 引用中，CC 不会立即重算 available | 用权威 diff 推导“已释放”，再通过 `PeriphAdd` 重建 |
| 管道点不中 | 节点层覆盖边层 | 缩小机器节点的命中范围，而不是提高边层级（避免边盖住容器） |
| 本地联调频繁 `SessionHasEditor` / `SessionIdNotExist` | mock CC 空闲 10 分钟断开、relay 会话保留、旧浏览器标签自动重连占位 | 测试时重启 relay + mock，并提高 `IDLE_TIMEOUT_MS`；这是联调环境问题，不是产品缺陷 |
| 重建容器只有 1 槽 | mock CC 只登记了部分外设容量 | 明确标注为 mock 限制；真实 CC 按设备容量初始化 |
| 键盘删除节点可能导致本地假删除 | React Flow 默认允许节点键盘删除 | 节点 `deletable: false`，删除统一走检视面板并发送协议请求 |

## 九、已知限制与风险

1. 外设 ID 仍不可修改，需要 CC 端新增原子协议（见 `M6-I4-外设ID能力分析.md`）。
2. 删除容器只释放“不再被任何容器使用”的外设；共享外设的槽位无法恢复。
3. 机器框只能从标题区域拖动/选中，框内空白区域用于选择管道。
4. 机器框合并、外设徽章拆分未实现。
5. 左上连接面板在窄缩放下可能遮挡画布左侧内容（既有布局问题）。
6. mock CC 容量数据不完整，重建容器槽位数与真实设备可能不同。
7. 真实 CC / Create 联调未执行；外设离线、缓存过期等场景未验证。
