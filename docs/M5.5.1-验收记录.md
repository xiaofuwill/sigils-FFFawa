## 一、W1 统一写入入口

**实现：**

- 新增 [syncGuard.ts](../apps/web/src/websocket/syncGuard.ts)：`classifyRequest()` 将请求分为 `mutation`（11 种工厂更新类型 + `BatchRequest`）、`read`（`FactoryGet`）、`session`（`SessionJoin` / `SessionClose`），未知类型直接抛错。
- `FactorySyncGuard.begin(reqId, request)` 是唯一写入门禁：
  - stale 时 mutation 抛「工厂状态不可信…写入已冻结」；
  - 已有 mutation pending 时抛「已有写入请求等待游戏端确认」；
  - read / session 不受写入门禁影响。
- [useSigilsConnection.ts](../apps/web/src/websocket/useSigilsConnection.ts) `sendRequest` 在生成 reqId 后立即调用 `guard.begin`，再设置超时定时器并发送。
- pending 收敛路径：成功/明确失败响应 `finish()`；超时 `noteTimeout()`；发送失败 `finish()`；socket close / 主动断开 `noteConnectionLost()`。

**结论：通过。**（`tests/sync-guard.test.ts` 第 1、2、11 项）

## 三、W3 stale / needsResync

进入 stale 的条件与实现位置：

| 条件 | 实现 |
|---|---|
| mutation 超时（结果未知） | `noteTimeout()` → `markStale("写入请求 X 超时，结果未知")` |
| 收到无法应用的 diff | `applyIncomingDiff` catch → `markStale("工厂变更无法应用：…")` |
| diff 格式 / 引用校验失败 | `applyDiffs` 内 `validateAndFreezeFactory` 抛错，同上 |
| 响应与当前请求/会话不一致 | 未匹配到 pending 的写入确认 → `markStale("收到与当前请求不匹配的写入确认…")` |
| 未加载快照就收到变更 | `applyIncomingDiff` 无 factory → stale |
| 快照请求失败 / 超时 / 校验失败 | `markStale`，保持冻结 |

stale 行为：

- 所有 mutation 被门禁拒绝；
- 画面保留（factory 不清空），顶部红色横幅显示原因，底部状态栏提示「数据不可信 · 写入已冻结」；
- stale 期间忽略 `CcUpdatedFactory` 与响应中的 diff；
- 不自动重试；迟到响应不能解除 stale；断线/重连不清除 stale；关闭提示不影响 stale。

**结论：通过。**（测试第 3、4、5、6、9、10 项）

## 四、W4 仅通过完整快照恢复

- 「重新同步工厂」按钮 / 横幅按钮发送只读 `FactoryGet`。
- 成功响应处理顺序：`validateAndFreezeFactory(factory)`（结构 + 引用）→ 原子替换 `factoryRef` 与 state → `clearStale()` → 状态恢复 connected。任何一步抛错都会 `markStale`，写入继续冻结。
- 快照失败（`ok:false`）、超时、校验失败都不会清除 stale。
- 代码路径上不存在「用 diff 解除 stale」的分支。

**结论：通过。**（测试第 7、8 项）

## 五、W5 测试

新增 [tests/sync-guard.test.ts](../tests/sync-guard.test.ts)，11 项：

1. pending mutation 时 6 类写入口（连线 / 边删除 / 删除键 / 机器拖动 / 分组编辑 / 批量）均被拒绝，pending 数保持 1。
2. 只读 `FactoryGet`、会话 `SessionJoin` 不被误拦；分类函数断言。
3. mutation 超时 → stale，所有写入口拒绝。
4. 超时后迟到响应 `finish()` 返回 null，stale 保持。
5. diff 应用失败 → stale。
6. diff 引用校验失败 → stale。
7. 快照请求超时 + 失败 → 持续 stale。
8. `clearStale()` 后才允许新写入（快照校验期间仍冻结）。
9. 断线/重连不解除 stale；断线时有未确认写入则新增 stale。
10. 超时后 pending 归零，不存在自动重试路径。
11. 明确失败响应正常收敛，不误标 stale。

**结论：通过。** `npx vitest run`：72 项 / 10 文件全部通过。
