## 3. Group 校验语义

### 3.1 GroupAdd

- `machineId` 必填、非空字符串，且对应 Machine 必须存在。
- `group.slots` 必须是非空、连续数组。
- `group.fluid ~= true` 时，每个 slot 必须有正整数 `slot`。
- `group.fluid == true` 时，slot 可以只有 `periphId`。
- 同一列表内重复 `(periphId, slot)` 拒绝。
- staged 执行完成后，同一 Machine 的任意两个 Group 引用同一 `(periphId, slot)` 时拒绝。

### 3.2 GroupEdit

- `edits.slots` 若出现，必须是非空、连续数组。
- `edits.fluid` 决定 slot number 是否必需；未提供时使用现有 Group 的 `fluid`。
- 最终归属规则与 GroupAdd 相同。

### 3.3 批量与单条一致性

- 单条消息与 BatchRequest 都先做 schema 校验，再做 machine/group 存在性校验。
- Batch 的槽位归属在全部 child 执行完、保存前统一检查。
- 因此合法的 split（先 GroupAdd、后 GroupEdit 移除源槽位）允许执行期临时重叠；最终仍重复则整批丢弃。
- 任一失败：不调用 `saveFactory`、不提交 staged、不发送 `ok=true`。

- **浏览器冒烟未执行**：UI 未改动，但未做端到端页面验证。
