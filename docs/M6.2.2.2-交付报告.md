| `GroupEdit` | `type/reqId/groupId/edits`；`edits`: `nickname/x/y/fluid/slots` | slots 规则同上；坐标有限数 | `id/machineId/未知键` |
| `GroupDel` | `type/reqId/groupId` | `groupId` 非空 | 额外键 |
| `PeriphAdd` | `type/reqId/periphId/options`；`options`: `nickname/x/y` | `periphId` 非空；options 可省略；坐标有限数 | `id/groups/periphId/未知键` |
| `PeriphDel` | `type/reqId/periphId` | `periphId` 非空 | 额外键 |

通用：外层数组非空、连续、从 1 开始；child 必须为 table；`type` 必须属于 11 种 mutation；`reqId` 若存在必须非空字符串；未知字段拒绝；必需字符串不得为空；数值必须有限。

## 4. 执行顺序与失败语义

```text
BatchRequest
→ countArray(requests)
→ 每个 child：table → type 字符串/白名单 → 顶层键白名单 → reqId → 字段级校验
   ├─ 失败：ok=false + message；Factory 不变；save 未调用；无成功 ack
   └─ 通过：staged = clone(factory) → ipairs 执行 → saveFactory 必须返回 true
            → commitFactory → ok=true + diff
```

- 校验在创建 staged 之前完成；任一 child 非法，前面的 child 也不会执行。
- 本轮未改变 M6.2.2 的执行/保存时序，也未新增事务或回滚承诺。
- 错误响应沿用 v4.3 `ConfirmationResponse` 的 `ok=false` + `error='UnknownError'` + `message`。
