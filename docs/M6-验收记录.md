## 一、I1 旧版行为调查

已检查 `SIGILS-upstream-master/SIGILS-master` 的客户端与 CC Lua 源码，输出 `docs/M6-旧版交互对照.md`。关键结论：

- 旧版画布上的“容器大框”是 `slot-group` 节点（`GroupNode.tsx`），内部渲染 `group.slots`；v4.3 没有独立的 Container 实体。
- 槽位拖动只在自己所属机器框内生效；结果是“该槽位拆成一个新分组”，源分组不能被拆空。
- 容器框拖动到同一机器内、同类型的另一容器框 = `combineGroups`：`GroupEdit` 目标 + `GroupDel` 源，同一个 `BatchRequest`；源容器管道级联删除。
- 合并排序为 `slot` 升序、再 `periphId` 字典序。
- 机器框拖动合并、外设徽章拆分存在于旧版，但不在 M6 范围，本版不实现。
- Machine 没有 Peripheral ID 字段，外设关联由 `Slot.periphId` 表达。

**结论：通过。**

## 二、I2 槽位拖动

实现：

- `GroupNode` 的槽位在 `canWrite` 且容器非液体、非折叠、槽位数 > 1 时可拖动（`application/sigils-slot`）。
- 落点必须是同一机器框；跨机器直接拒绝并提示。
- 请求：`buildGroupSplit` → `GroupAdd`（新容器仅含该槽位，沿用原昵称，写入相对机器框的 `x/y`）+ `GroupEdit`（源容器移除该槽位），单个 `BatchRequest`。
- 源容器只剩一个槽位时，构造器抛“不能把 Group 的全部槽位拆出”，不发送请求。
- 不新增“合并槽位”按钮/功能。

证据：

- 构造器测试：`tests/container-merge.test.ts`（位置、昵称、源容器剩余槽位、单槽拒绝、液体拒绝）。
- 协议模拟：`tests/protocol-sim.test.ts`「a split runs as one ordered batch…」— Fake CC 应用后 `x/y` 与槽位一致，客户端 diff 打平结果与服务端相同。
- 浏览器：槽位 chip 的 `draggable=true`、拖拽提示存在；**拖动动作本身未自动化验证**。

**结论：通过（构造器 + 协议模拟）；浏览器拖动动作未执行。**

## 三、I3 容器框合并

实现：

- `canMergeGroups`：同机器、Item↔Item / Fluid↔Fluid、不能合并到自身、源不能为空、槽位不能重复。
- `buildGroupMerge`：`BatchRequest` = `GroupEdit`（目标 slots 合并排序）+ `GroupDel`（源）。
- UI：拖动分组节点时对兼容目标做命中测试，目标卡片绿色高亮 + 「松开以合并到此容器」；松开后确认框列出源容器槽位数与将被级联删除的管道数。
- 失败/取消：不发请求；取消确认时仅保存拖拽后的位置。
- 不做乐观更新；合并结果等待 CC 的 diff。

证据：

- 构造器测试：`tests/container-merge.test.ts` 10 项（成功消息结构、跨机器、自身、类型混用、重复槽位、未知容器）。
- 协议模拟：`tests/protocol-sim.test.ts`「a container merge keeps slot identity…」— 目标槽位 1–3、源容器删除、机器 `groups` 更新、关联管道删除、客户端 diff 打平一致。
- 浏览器（生产构建 :4173 + relay + mock CC）：真实鼠标拖动 Overflow → Main，Main 绿色高亮，确认框“2 个槽位会并入目标容器…”，确认后 Main 显示槽位 1–6、Overflow 消失；重连后重新 `FactoryGet` 结果一致（非前端伪造）。
- mock CC 事件日志记录到 `BatchRequest [GroupEdit,GroupDel] ok=true`。

**结论：通过。**

## 四、I4 Machine 的 Peripheral ID

- 现状分析见 `docs/M6-I4-外设ID能力分析.md`：`Machine.id` 即外设 ID，分组 ID 与槽位 `periphId` 都由它派生；`MachineEdit` 只写对象字段，不会重命名 map key / 分组 ID / 引用，故不能安全改 ID。
- 本版 UI：机器检视面板新增只读「外设 ID」列表 + 说明，不提供伪编辑；昵称编辑保留并注明只影响显示。
- 协议提案：`MachineReassignPeriph { machineId, newPeriphId }`，由 CC 端原子完成校验与全部引用重写，失败不产生部分修改。

证据：浏览器实测机器 Storage / Missing Chest 面板均显示「外设 ID」及说明。

**结论：能力分析 + 协议提案完成；功能实现需 CC 端协议扩展。**

## 七、已知限制

1. **机器框合并未实现**：旧版 `combineMachines` 会合并同名分组并删除源机器；本版只持久化位置。原因：破坏面大且不在 M6 任务书。
2. **外设徽章拆分未实现**：旧版用多条非原子请求把外设拆成新机器；与“无事务保障不实现”的总则冲突，留给后续协议设计。
3. **外设 ID 不可编辑**：需要 CC 端新增原子消息，提案已提交，未实现。
4. **布局遮挡**：窄视口下左上悬浮面板仍可能遮挡靠左节点（既有问题），可缩放/隐藏面板规避。
5. **mock 固定夹具**：`tools/mock-cc.ts` 固定 Main 4 槽 + Overflow 2 槽，因此“合并后 6 槽单行”的视觉复验未在修复后重做；已通过 `box-sizing: border-box` 修正，4 槽位实测无裁剪。

## 八、M6.1 测试反馈修复（2026-11-12）

用户实测反馈三项问题，均已在 M6.1 修复：

### 1. 容器末尾槽位被遮挡

- **根因**：React Flow 默认节点 wrapper 自带 `padding: 10px` 与边框；节点宽高按内容计算，导致 9 列槽位实际可用宽度少约 21px，最后一列与最后一行被容器 `overflow: hidden` 裁切。
- **修复**：节点 `style` 显式清零 `padding / border / background`；`.group-node` 使用 `box-sizing: border-box`；槽位容器改为固定列数的 CSS Grid（`repeat(columns, 26px)`）。
- **验证**：27 槽位容器实测 3 行 × 9 列；`.group-slots` `clientWidth = scrollWidth = 250`；所有 chip 均在卡片边界内。

### 2. 移除「分组槽位」面板

- 删除右侧「分组槽位」卡片（槽位勾选 / 保存槽位 / 移动槽位）及对应状态与处理函数。
- 槽位交互只保留拖动：拖单个槽位拆出新容器、拖整个容器合并。
- 「可恢复槽位」卡片一并移除，改为按外设释放（见下）。

### 3. 删除容器后回到「可用外设」

- 删除容器后，检测不再被任何容器引用的外设（且不是缺失外设），加入「可用外设」列表并标记「已释放」；点击「添加为机器」发送 `PeriphAdd` 重建默认容器。
- 释放只在权威 Factory 更新后计算，删除失败不会误报；重连/离线时释放列表清空（会话级）。
- 验证：删除 27 槽容器 → 可用外设出现 `minecraft:barrel_0`（已释放）→ 添加为机器后机器与容器重建。
- **限制**：若同一外设还被机器内其他容器使用，则不会释放；此时被删容器的槽位无法恢复。mock CC 的 `inventories` 未登记 barrel 容量，重建实测为 1 槽；真实 CC 按外设实际槽位数创建。

### 4. 名称与槽位显示

- `Inventory` → 物品槽、`Fluid tank` → 液体槽：仅显示映射，不改写游戏端昵称。
- 液体容器槽位改为与物品槽一致的编号（1、2、3…），不再显示「液」。

## 九、M6.2 管道与外设 ID 修正（2026-11-12）

用户反馈：管道无法删除、管道无法命名、机器标题应显示外设原始 ID。

### 1. 管道无法删除

- **根因**：机器框节点覆盖了机器内部的整条管道，边的命中区被节点层挡住，无法选中；同时节点层没有显式删除按钮，键盘删除又只注册了 `Delete`。
- **修复**：
  - 机器节点 `pointer-events: none`（标题 / 元信息保留 `auto`），框内管道可被点选；机器框底色改为半透明，管道可见；
  - 检视面板新增「删除管道」按钮，发送 `PipeDel`；
  - `deleteKeyCode` 同时支持 `Delete` 与 `Backspace`；
  - 机器 / 容器节点 `deletable: false`，避免键盘删除只在本地移除节点而不通知 CC。

### 2. 管道无法命名

- 检视面板新增「管道名称」输入，与过滤表达式一起通过 `PipeEdit { nickname, filter }` 提交。
- 边标签显示「名称 (过滤表达式)」；无名称时显示过滤表达式或 mode。

### 3. 机器显示外设原始 ID

- 机器节点标题固定为 `machine.id`（即外设原始 ID），昵称单独显示为「别名 · …」。
- 检视面板、删除确认、底部统计统一使用原始 ID / 容器术语。
