## 一、P0-01 未分配槽位新建分组

**问题：** `createCandidates` 的默认分支从「本机已占用槽位」集合里再减去同一集合，候选恒为空；“从未分配槽位新建分组”没有可靠数据来源。

**处理：**

- 界面上移除「未分配的槽位」来源选项，来源下拉只能选一个已存在的分组。
- 卡片改为「拆分分组」，并常驻提示：游戏端快照不含库存总容量，无法确认未分配槽位，只能从现有分组拆出。
- `buildGroupCreate()` 保留为唯一受校验的构造路径，但**不从 UI 调用**，等 CC 提供容量枚举 API 后再开放。
- 禁止用最大已见槽位、常见箱子容量或外设类型推算总容量。

**证据：**

- 源码：[App.tsx `createCandidates`](../apps/web/src/App.tsx)、[groupActions.ts `buildGroupCreate`](../apps/web/src/groupActions.ts)
- 测试：`tests/group-actions.test.ts` —「returns no slots for a machine that has no groups yet」
- 浏览器实测：展开「拆分分组」→ 提示立即可见；来源下拉仅「选择来源分组 + Main Inventory + Overflow」，无未分配槽位选项；选 Main Inventory 后出现 4 个槽位复选框，未勾选时按钮禁用。

**结论：通过**（离线无会话时按钮保持禁用，属于预期）。

## 二、P0-02 重复槽位 fail closed

**问题：** `normalizeSlots` 对重复 `(periphId, slot)` 静默 `continue`，与“重复即拒绝”的设计意图不符。

**处理：**

- 重复项直接抛错：`槽位 <periphId>#<slot> 重复出现；请先修正槽位列表。`
- 同一槽位被两个分组占用时，错误信息带上占用者分组 ID。
- 液体槽位语义保持不变：`slotKey` 对缺失 `slot` 返回 `periphId#fluid`，不会被当成整数槽位或 0。

**证据：**

- 测试：`tests/group-actions.test.ts`
  - 「rejects duplicate slots instead of silently collapsing them」（覆盖创建 / 拆分 / 编辑 / 移动四条路径）
  - 「names the owning group when a slot is already claimed」
  - 「keeps fluid slots distinguishable from numbered item slots」
- 数据模型：`tests/fluid-group.test.ts` 仍要求液体分组接受缺失 `slot`，普通分组必须为整数。

**结论：通过。**

## 三、P0-03 写操作与删除操作安全性

| 项 | 处理 | 证据 |
|---|---|---|
| 不做乐观更新 | 保持原设计：只应用 `ConfirmationResponse` / `CcUpdatedFactory` 的 diff | `useSigilsConnection.applyDiffs` |
| 未确认请求不自动重发 | 断线清空 pending；不发重试 | `clearPending`、socket `close` 分支 |
| 删除展示影响范围 | Group：关联管道数，若是最后一个分组还提示会删除哪台机器；Machine：分组数 + 关联管道数；外设：清除槽位数 + 会被删除的分组与管道数 | `App.tsx` `deleteSelectedNode` / `removeMissingPeripheral` |
| Batch 只允许白名单类型 | 发送前校验顶层消息与每个子请求类型，未知类型直接拒绝，不依赖 CC 的 `ok:true` | `useSigilsConnection.assertSupportedRequest`、`packages/protocol.isFactoryUpdateRequestType` |
| 超时提示“结果未知” | 文案改为「请求超时，结果未知；请点击“重新同步工厂”确认当前状态」 | `useSigilsConnection` 超时回调 |
| 防止重复点击写入 | 新增 `pendingCount`，有请求在飞时禁用所有写按钮并提示「等待游戏端确认」 | `useSigilsConnection.pendingCount`、`App.tsx canWrite` |
| 删除后引用一致性检查 | diff 应用后仍走 `validateFactoryReferences`，失败即报错并停止增量应用 | `applyDiffs` → `validateAndFreezeFactory` |

**结论：通过**（浏览器实测：离线时所有写按钮禁用；会话中 pending 行为需真实联机复验，列入 M6）。
