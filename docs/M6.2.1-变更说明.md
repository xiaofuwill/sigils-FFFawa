# M6.2.1 — 变更说明（Stability & Sync Safety）

**日期：** 2026-11-12
**版本：** M6.2.1
**性质：** 稳定性补丁，不新增编辑器功能
**协议：** SIGILS v4.3（未修改）

---

## 一、修复的问题

| # | 问题 | 处理 |
|---|---|---|
| 1 | 响应仅凭 `reqId` 被认定为有效 | 新增 `responseGuard.ts`：envelope → reqId → respondingTo → Session → epoch → payload 全链路校验 |
| 2 | pending / guard 在响应语义校验前被清理 | 所有校验（含 FactoryGet 结构与引用校验）通过后才 `settlePending` |
| 3 | FactoryGet 快照无条件 `clearStale` | 增加同步屏障与覆盖校验：快照必须晚于所有 mutation；不满足则保持 stale |
| 4 | 同一 Session 并发 FactoryGet | `FactorySyncGuard.begin` 对 FactoryGet 单飞；UI 在同步期间禁用按钮并显示「正在同步…」 |
| 5 | Session / 连接代际隔离不完整 | pending 记录 `sessionCode + epoch`；每条新连接递增 epoch；切换会话主动清空 pending |
| 6 | BatchRequest 原子性未审计 | 完成真实 CC Lua 审计（结论 C：单次持久化但非事务），见 `M6.2.1-CC控制器审计.md` |
| 7 | 多条 PipeDel 逐条发送与单飞门禁冲突 | 新增 `buildPipeDeleteBatch`：单条直接 `PipeDel`，多条合并为一个 `BatchRequest` |

## 二、行为变化（有意为之）

1. **未知 / 重复 / 错配 / 迟到响应不再修改状态**：不再把“未匹配的写入确认”升级为 stale，只记录日志并忽略；对应的 pending 仍会在超时后 fail closed。
2. **载荷无效的响应不清理 pending、不改变 stale**：pending 保留到超时，期间单飞门禁继续生效。
3. **FactoryGet 结构与引用校验失败时不替换画面、不改变 stale**（M5.5.1 会立即标 stale；本轮按 02 规范改为“无状态变化 + 等超时”）。
4. **快照覆盖校验**：FactoryGet 发出后又有 mutation 时，快照不能解除 stale；需要再次显式同步。
5. **同步按钮状态**：FactoryGet 在途时按钮禁用并显示「正在同步…」。
6. 失败响应（`ok:false`）仍是明确结果，匹配通过后立即收敛 pending；FactoryGet 失败会进入 stale。
